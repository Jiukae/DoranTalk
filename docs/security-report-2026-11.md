## 2. 시험 방법

- **기준**: OWASP Top 10 (2021) — 접근 통제 실패(A01), 암호화(A02), 주입(A03), 불안전한 설계 · 과다 사용(A04), 보안 설정(A05), 오래된 부품(A06), 인증(A07), 무결성(A08), 서버 요청 위조(A10) — 과 Supabase 보안 점검 항목(모든 표 RLS, 함수 권한, 저장소 정책, 공개 키만 앱에)을 따랐어요.
- **실제 Supabase와 같은 조건**: Supabase는 새로 만든 표 · 함수에 "누구나 쓸 수 있는 권한"을 기본으로 줘요. 그래서 시험용 데이터베이스에도 똑같이 기본 권한을 준 다음(`supabase/tests/supabase_defaults.sql`) 설계 파일을 실행했어요. 권한을 빼앗는 걸 하나라도 놓치면 시험이 찾아내요.
- **공격자 역할**: 로그인 안 한 사람 · 막 가입한 사람 · 외부인 · 같은 그룹 멤버 · 아이(만 14세 미만) · 그룹을 나간 사람 · 운영자인 척하는 사람.
- **고치기 전 · 후 비교**: 같은 시험을 지금 운영 중인 버전 14 코드와 고친 버전 15 코드에 각각 돌렸어요. 업데이트 파일(`v14_to_v15.sql`)로 올린 데이터베이스가 새로 설치한 것과 **구조 · 보안 규칙 · 함수 권한 · 표/칸 권한 · 창고 설정까지 똑같은지**도 확인했고, 업데이트한 데이터베이스에서도 258개 시험이 모두 통과했어요.
- **운영 서버는 읽기만**: www.dorantalk.com 과 Supabase 에는 앱에 이미 들어 있는 공개 키로만 요청했어요. 가입 · 글쓰기 · 삭제는 하지 않았고, 시도한 쓰기는 모두 거절되는 것까지 확인했어요.
- **범위 밖**: 많은 요청을 쏟아붓는 부하(DoS) 공격, Supabase · Vercel · 구글 같은 회사 자체 서버, 피싱 같은 사람 속이기, 휴대폰 운영체제.
- **다시 돌리는 법**: `supabase/tests/security_run.sh` (데이터베이스 258개) · `supabase/tests/live_check.sh` (운영 서버 읽기 전용 108개).

## 3. 발견한 문제와 고친 방법

### 🟠 F1. 사진 창고를 아무나 가득 채울 수 있었어요 (중간)
- **어떻게**: 가입만 하면 **프로필 사진 칸**에 50MB 파일을 개수 제한 없이 올릴 수 있었어요. 동영상 "하루 10개" 한도도 이 칸으로 피할 수 있었고, 사진 칸도 하루 개수 제한이 없었어요. 사진 칸에 `.html` 같은 다른 파일, 정해진 폴더보다 깊은 곳에도 올라갔어요.
- **피해**: Supabase 무료 저장 공간(1GB)이 가득 차면 **모든 가족이 사진을 못 올려요.** (50MB × 20개면 끝)
- **고침 (버전 15)**: 한 사람이 하루에 **사진 300장 · 동영상 10개 · 프로필 사진 20번 · 모두 합쳐 500MB**까지. 프로필 사진 칸은 사진(jpg · png · webp)만, 사진 칸은 사진 · 동영상만, 정해진 폴더에만.
- **확인**: DB-R07 ~ DB-R12 (고치기 전 6개 모두 뚫림 → 고친 뒤 통과). 보통 쓰는 정도(하루 사진 수십 장)는 그대로 돼요.

### 🟠 F2. 다른 사람의 휴대폰 알림을 끊을 수 있었어요 (중간)
- **어떻게**: 아이디만 알면 그 사람을 초대한 뒤, 알림 서버 대신 데이터베이스 함수를 **직접** 불러 그 사람 휴대폰의 **알림 주소**를 받아 올 수 있었어요. 그 주소를 자기 것으로 다시 등록하면, 상대 휴대폰으로 가던 가족 알림이 끊겼어요. (상대가 앱을 다시 열 때까지, 그리고 몇 번이고 반복 가능)
- **알림 내용을 훔치거나 가짜 알림을 보낼 수는 없었어요.** 알림을 보내려면 알림 서버에만 있는 비밀 열쇠(VAPID)가 필요하기 때문이에요.
- **고침 (버전 15)**:
  1. 다른 사람의 기기 주소는 **같은 암호 열쇠를 가진 바로 그 휴대폰**에서만 넘겨받을 수 있어요. (주소만 알아낸 사람은 못 가로채요)
  2. **알림 서버 전용 열쇠**(선택, 권장): 열쇠를 넣으면 가족 기기 주소 목록은 **알림 서버만** 받을 수 있어요. 앱에서 직접 부르면 빈 목록이 와요. → [20단계 할 일 3](step20-security.md)
- **확인**: DB-U03 · U07 · U09 · R16, API-33 · API-35 (고치기 전 뚫림 → 고친 뒤 통과). 같은 휴대폰에서 다른 계정으로 로그인하면 알림이 넘어가는 정상 기능(DB-U04)은 그대로예요.

### 🟡 F3. 가족 달력으로 알림 폭탄을 보낼 수 있었어요 (낮음)
- **어떻게**: 일정 개수에 제한이 없어서, 그룹 멤버 한 명이 "오늘" 일정을 수천 개 만들면 가족 모두에게 알림이 쏟아질 수 있었어요.
- **고침**: 그룹마다 일정 **300개**, 한 사람이 하루 **30개**, 달력 알림은 그룹마다 하루 **20번**까지.
- **확인**: DB-R13 ~ DB-R15.

### 🟡 F4. 초대 메일에 가짜 사이트 주소를 넣을 수 있었어요 (낮음)
- **어떻게**: 그룹 이름을 `evil.com/로그인` 처럼 지으면 공식 메일(admin@dorantalk.com)에 그 글자가 들어가고, 메일 앱이 링크로 바꿔 보여 줄 수 있었어요. (HTML 태그는 원래 글자로 바뀌어 안전했어요)
- **고침**: 메일 속 그룹 이름의 `. : / @` 를 띄어 써서 주소처럼 보이지 않게. 메일 버튼은 늘 `https://dorantalk.com/#/…` 로만 가요.
- **확인**: DB-M02 · M03 (DB-M01 · M04 ~ M07 은 원래도 통과).

### 🟡 F5. 운영자 확인에 "이메일 인증"이 빠져 있었어요 (낮음)
- **어떻게**: 운영자는 `admin@dorantalk.com` 주소로만 알아봤어요. 지금은 이 계정이 이미 있어서 아무도 같은 주소로 가입할 수 없지만, 만약 운영자 계정을 지우면 누군가 이 주소로 가입만 해도(메일 인증 전) 운영자 통계를 볼 수 있는 구조였어요.
- **고침**: **이메일 인증까지 마친** 운영자 계정만 운영자 화면 · 쿠폰 만들기 · "관리자" 같은 이름을 쓸 수 있어요.
- **확인**: DB-V07 · V08 (인증 마친 운영자는 그대로 된다는 DB-V09 도 통과).

### ⚪ F6. 알림을 누를 때 열리는 주소를 확인하지 않았어요 (참고)
- 알림 속 주소가 다른 사이트면 그 사이트가 열릴 수 있는 구조였어요. 알림 내용은 우리 알림 서버만 만들 수 있어서 실제로 악용하기는 어려워요.
- **고침**: 서비스 워커가 **도란톡 안의 주소만** 열고, 아니면 홈을 열어요. (SW-01 · 02 · 04, 앱 화면 쪽은 원래도 확인함: WEB-19)

### ⚪ F7. 계산용 함수 2개를 로그인 없이 부를 수 있었어요 (참고)
- `is_video_path` · `media_summary` (파일 이름이 동영상인지, "사진 2장" 같은 문장 만들기). 정보가 새지는 않아요.
- **고침**: 로그인한 사람만, `media_summary` 는 알림 서버 내부에서만. (DB-A07 · A08-10, 운영 서버 LIVE-F50 · F51 은 업데이트 후 통과)

## 4. 고치지 않고 알고 넘어가는 것 (남은 위험 · 권장)

| 내용 | 왜 그대로 두나 | 권장 |
|---|---|---|
| 실시간(Realtime)의 "지움" 신호 | Supabase 실시간 기능의 알려진 한계로, 누가 그룹을 나가거나 하트를 지울 때 생기는 "지움" 신호는 보안 규칙으로 걸러지지 않아요. 다만 들어 있는 건 **무작위 번호(UUID)뿐**이라 이름 · 글 · 사진은 알 수 없어요. | 그대로 (Supabase 공식 문서의 제약) |
| 비밀번호 최소 6자 | 할머니 · 할아버지도 쓰기 쉽게 | 운영자 계정은 **12자 이상 · 다른 곳에서 안 쓰는 비밀번호**. Supabase 유료(Pro)가 되면 "유출된 비밀번호 막기" 켜기 |
| 무료 저장 공간 1GB | 하루 한도를 둬도, 계정을 여러 개 만들어(각각 이메일 인증 필요) 작정하고 채우면 완전히 막긴 어려워요 | 한 달에 한 번 Supabase **Usage** 보기 (10단계 G) |
| 가족끼리는 믿는 구조 | 같은 그룹 가족은 서로의 일정을 고칠 수 있고, 채팅을 많이 보낼 수 있어요 (다른 채팅 앱과 같아요) | 모르는 사람 초대는 거절하기 |
| 나이(만 14세 미만)는 스스로 고름 | 보통 쓰는 방법이에요. 대신 보호자 동의 링크는 7일 · 한 번만 · 보호자 비밀번호 다시 확인 | 그대로 |
| 사진 주소는 1시간 동안 유효 | 사진은 1시간짜리 서명 주소로만 보여요. 그 주소를 밖에 보내면 1시간 동안은 열려요 | 가족 사진 주소를 다른 곳에 붙여넣지 않기 |
| 안드로이드 앱 `allowBackup=true` | 앱 안에 비밀 정보를 저장하지 않아요 (로그인 정보는 크롬이 관리) | 다음 APK 를 만들 때 `false` 로 |
| 설계 파일(schema.sql)이 사이트에서 보임 | 비밀 값이 하나도 없어요 (LIVE-10 · ST-01 · ST-02). 보안은 "숨기기"가 아니라 "규칙"으로 지켜요 | 그대로 |
| 로그인 주소 허용 목록 (밖에서는 확인 불가) | 비밀번호 찾기 · 가입 인증 메일의 링크가 돌아올 주소 목록이에요. 공개 키로는 볼 수 없어서 시험하지 못했어요 | Supabase → **Authentication → URL Configuration** 의 Site URL · Redirect URLs 가 `https://www.dorantalk.com` · `https://dorantalk.com` 뿐인지 확인 (`*` 같은 넓은 주소 ❌) |
| 가입 로봇 막기(CAPTCHA) 없음 | 가입은 이메일 인증이 필요해서 로봇이 쉽게 쓰지 못해요 | 이상한 가입이 늘면 Supabase 의 CAPTCHA(Turnstile) 켜기 |
| 운영자 2단계 인증 없음 | 앱에 아직 2단계 인증 화면이 없어요 | 지금은 튼튼한 비밀번호로. 나중에 2단계 인증(OTP) 추가 |

## 5. 운영 서버에서 확인한 것 (읽기 전용, 108개)

- **사이트**: https 만 · HSTS 2년 · 보안 정책(CSP)이 저장소 설정과 글자 하나까지 같음 · 틀 넣기 금지 · `.git` `.env` 노출 없음
- **로그인 설정**: 이메일 인증 필수 · 익명 로그인 꺼짐 · 이메일 로그인만 · 데이터베이스 설계도(OpenAPI) 숨김 · GraphQL 꺼짐
- **로그인 안 한 사람**: 18개 표 전부 막힘 · 함수 56개 중 가입 · 확인용 5개만 열림 (+ 계산용 2개는 버전 15 뒤 닫힘)
- **사진 창고**: 비공개 · 파일 목록 안 보임 · 가짜 서명 주소 거절 · 익명 올리기 거절
- **위조 로그인**: 관리자(service_role) 위조 · 서명 없는 것(alg: none) · 널리 알려진 예시 열쇠 — 모두 거절
- **알림 서버**: 로그인 없이 · 위조로 · 이상한 종류로는 못 보냄
- **할 일 4개 (⏳)**: 운영 데이터베이스가 아직 버전 14 · 알림 서버가 아직 예전 코드(19단계 "다시 올리기"가 안 됨) → [20단계 안내서](step20-security.md) 를 하면 끝나요.
